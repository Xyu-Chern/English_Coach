Engineering and collaboration rules

Ownership

The owner writes the core flow to learn. AI helps decompose problems, explain contracts and review code. Start each change with one observable behavior, such as zero embedding calls for an empty document list. The owner resolves scope changes and updates design.md.

Module boundaries

Preserve ingestion, chunking, storage, search, coach and evaluation boundaries. State inputs, outputs and failures. Commit transcript and completion mark together; reruns should preserve version identity. Keep provider and SQL details in their adapters.

Evidence and runtime limits

Distinguish model advice from publisher wording. Preserve quote, provenance and rights metadata; wording alone cannot prove semantic fit. Validate input, bound calls and distinguish not-ready, no hits and service errors. The translation demo only translates.

Reporting improvements

Save a failing input and expected behavior before changing prompts, search or stopping. Compare on fixed tasks, corpus, model configuration and budgets; report quality, latency and cost. Distinguish archived runs, offline checks and fresh measurements. Keep keys out of version control and minimize learner text in logs.

Document ownership

design.md owns scope and acceptance, Goal.md owns progress and dependencies, AGENTS.md owns collaboration guidance. Maintain English, Chinese and Korean sections and owner questions. Link claims to code, traces or a working demonstration.

规则文档

谁写代码，谁做判断

按负责人的学习目标，核心流程由本人手敲，AI 帮拆问题、解释输入输出、审查已写代码。每次先明确一个可验收的小行为，例如“空文档列表时不调用 embedding”。需要变更产品范围时，由负责人决定并更新 design.md。

模块之间怎样交接

保留采集、分块、存储、检索、教练和评测的现有边界。说明每次交接的输入、输出、失败结果。数据库写入保持一致：新增字幕和完成标记一起提交；采集重跑不会重复新增同一版本。模型供应商与数据库细节留在各自适配层。

证据与运行边界

区分“模型建议怎么说”和“播客确实怎么说”。展示引句时保留原文、出处和许可信息；文字命中不能代替语义判断。保留输入校验和调用次数上限。资料未就绪、查无结果和服务故障分别处理。翻译 demo 只翻译输入。

如何声称改进

改提示词、搜索或结束条件前，先保留一条失败输入和期望行为。对照时固定题目、语料、模型配置和预算；记录质量、成本与耗时。旧报告、离线用例和本次新测量分别标明。密钥不进版本库；日志尽量避免记录不必要的学习者原话。

文档归属

design.md 记决定与验收口径；Goal.md 记任务、依赖和进度；AGENTS.md 记项目协作要求。项目文档完整保留英中韩三版及负责人判断题。展示给评审的能力要能用源码、运行记录或现场演示核验。

개발·협업 규칙

역할

학습을 위해 핵심 흐름은 책임자가 직접 작성한다. AI는 문제 분해·입출력 설명·검토를 돕는다. 변경마다 관찰 가능한 행동을 정한다. 범위 변경은 책임자가 결정하고 design.md에 기록한다.

모듈 경계

수집·분할·저장·검색·코치·평가 경계를 유지한다. 입출력과 실패를 기록한다. 자막과 완료 표시를 함께 커밋하고 재실행 시 같은 버전을 중복 생성하지 않는다. 공급자·SQL 세부 사항은 해당 계층에서 처리한다.

근거와 실행 한도

모델 제안과 실제 발언을 구분한다. 인용·출처·권리 정보를 보존하며 표현 일치만으로 의미를 확정하지 않는다. 입력과 호출 횟수를 제한하고 준비 안 됨·검색 결과 없음·장애를 구분한다. 번역 데모는 번역만 수행한다.

개선 보고

프롬프트·검색·종료 조건을 바꾸기 전에 실패 입력과 기대 동작을 남긴다. 문항·코퍼스·모델·예산을 고정해 품질·시간·비용을 비교한다. 기존 결과·오프라인 검사·새 측정을 구분한다. 비밀 키를 커밋하지 않고 불필요한 학습자 원문 기록을 줄인다.

문서 관리

design.md는 범위·검수, Goal.md는 진행·의존 관계, AGENTS.md는 협업 지침을 관리한다. 영어·중국어·한국어 본문과 책임자 질문을 유지한다. 주장에는 코드·기록·시연 근거를 연결한다.
