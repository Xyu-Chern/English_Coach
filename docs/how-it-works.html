STEP 1
Ask in your own language, and get English expressions with real podcast quotes

A person who speaks English as a second language (for example, a Korean or Chinese speaker) asks in their own language: "How do I say this in English?" The coach returns up to 3 natural English expressions. For each expression it attaches one quote from a real podcast that uses it. Code checks that each quote really is in the corpus.

Confidence intervals: paired bootstrap at the task level on the 43 answerable tasks (4,000 resamples, seed 7). Tasks whose result changed across the 3 runs: 9 for the Baseline and 5 for the agent (= pass@3 − pass^3).

  • Where the agent is better: rereading the quotes it already found and fixing the ones with the wrong meaning. This is why answers with all three items good (strict pass) and tasks that pass all 3 times (pass^3) went up.
  • Where the Baseline is better: persistence. While a slot is empty, it keeps searching to the end, as the rule says. The agent sometimes finishes early with budget left (the STEP 5 example).
  • Cost: the agent uses about 1.5× the tokens, and its average latency is about 7 seconds longer.
  • What we learned about the design: we also tested letting the agent do the first search itself, but the pass rate dropped a lot. A fixed first stage is good at searching widely, and the agent worked best when its role was to read that result and fix it.
CautionThe judge is an LLM, not a person. The 50 tasks were also used during development, so this is not a fully held-out test. With only 3 repeats, pass^3 can change from one run to the next.

  • 智能体更擅长的：重新阅读已经找到的引文，修正意思不对的那些。因此三项全部良好的答案（严格通过）和 3 次全部通过（pass^3）都增加了。
  • 基线更擅长的：坚持。只要还有空槽位，就按规则一直找到最后。智能体有时会留着预算提前结束（STEP 5 的示例）。

STEP 1
자기 언어로 물으면, 실제 팟캐스트 인용이 붙은 영어 표현을 돌려줍니다

영어가 제2언어인 사람(예: 한국어·중국어 사용자)이 "이 말을 영어로 어떻게 하지?"라고 자기 언어로 묻습니다. 코치는 자연스러운 영어 표현을 최대 3개 돌려주고, 표현마다 실제 팟캐스트에서 그 표현을 쓴 원문 인용을 하나씩 붙입니다. 인용이 코퍼스에 정말 있는지는 코드가 확인합니다.

실제 입력과 출력 (평가 기록 그대로)

입력회의에서 시니어 개발자 의견에 정중하게 반대하고 싶어요. (과제 ko-func-ctx-1)
출력 1I see where you're coming from, but I'm not sure that approach would scale here.인용: "And I see where you're coming from with that." — Making DNSimple
출력 2Could we play devil's advocate for a second? What if we kept the current setup?인용: "…to kind of play devil's advocate here…" — Sophie is the bomb diggity
출력 3That's a fair point, but have you considered how it would work with the legacy service?인용: "Yeah, that's a fair point." — Opening up the opinion box

출처 밖 요청(다른 팟캐스트·드라마), 영어 표현과 무관한 요청(날씨, 발음 평가), 프롬프트 주입은 아무것도 지어내지 않고 짧게 거절합니다.

주황 = 둘이 공유, 파랑 = 코드가 정함, 보라 = LLM이 정함, 초록 = 출력, 노랑 = 코퍼스. 점선 = 검색이 코퍼스를 읽음.
핵심두 시스템은 같은 첫 단계 결과에서 출발하고, 같은 도구·같은 예산·같은 검증기를 씁니다. 다른 것은 "다음에 무엇을 할지"를 코드가 정하느냐(Baseline), LLM이 정하느냐(에이전트) 하나뿐입니다.

코치는 인용을 지어내지 않습니다. 미리 만들어 얼린 코퍼스에서 문단을 찾고, 모델이 고른 문구가 그 문단에 글자 그대로 있는지 코드가 확인합니다. 이 탭은 코퍼스가 만들어지는 과정, 검색 규칙, 검증 규칙을 설명합니다.

검색코드후보마다 1번, 문단 3개씩후보 6개를 한 번에 넓게 찾음

핵심 구절: 표현에서 다시 쓸 수 있는 가장 짧은 덩어리(1–6단어). 예: "Let's not jump to conclusions about the cause."의 핵심 구절은 "jump to conclusions". 코퍼스 전체 건수가 0이면 그 구절은 코퍼스에 한 번도 나오지 않는다는 뜻이라, 다른 표현으로 바꾸는 근거가 됩니다.

초록 = 합격 인용, 노랑 = 검증은 통과했지만 뜻이 다른 인용, 빨강 = 실패, 회색 = 아직 예문 없음.
  1. 검증기는 문자만 봅니다. "not to treat"라는 구절이 문자 그대로 있어서 칸 1이 통과했지만, 뜻은 요청과 달랐습니다. 두 시스템 모두 이 칸을 그대로 안고 갔습니다.
  2. 에이전트는 문제를 알아채고도 행동하지 않았습니다. 검토 글에 "고용주 이야기"라고 적었지만 유지했고, 칸 3에도 같은 종류의 인용을 붙였습니다.
  3. 남은 턴을 두고 일찍 끝냈습니다. Baseline은 규칙상 빈 칸이 있으면 끝까지 돌기 때문에 라운드 3에서 맞는 인용을 찾았습니다.
다음 개선 후보예산이 남았고 뜻을 의심한 칸이 있으면 끝내지 못하게 하기, 짧은 조각만 같은 인용에 뜻 검사를 한 번 더 하기. 둘 다 동작이 바뀌므로 새 실행으로 확인해야 합니다.
